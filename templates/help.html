这个工具是做什么的？

每季 Dior 发来的 Sell-Thru Map（销售进度表）里，需要补货的款式会 标黄——表里 E1 单元格的备注写得很清楚： “标黄款式后续有REORDER补货”。以前要靠手工逐个整理，现在工具会自动完成：

  1. 扫描 Sell-Thru Map 的所有工作表，找出每一个标黄的 SKU；
  2. 去掉 SKU 末尾的颜色码（X + 4 位），得到基础款号 （例如 644S16B7E72X5805 → 644S16B7E72）；
  3. 在保存好的库存查询表里，把这些款号的 所有颜色和尺码都找出来；
  4. 生成一份可以直接使用的 ProductsList 工作簿，下载即可。

开始前需要准备什么？

  1. 登录账号：由管理员在“团队”页为你创建 — 你会收到邀请邮件自行设置密码，或由管理员直接告知初始密码。 每次运行都会记录是谁上传的、谁确认生成的。
  2. Sell-Thru Map（.xlsx）：需要补货的款式已经标黄， 每次处理都要上传。
  3. 库存查询表（.xlsx）：必须是标准的 13 列导出文件 （Barcode、Sku、Division、Department、Season、Product reference、 Color code、Size、Quantity、Unit Weighted Average Cost、 Unit Retail Price incl. tax、Item Type、Path）。 只在第一次使用或库存数据更新时上传一次，工具会自动保存。

第一次使用：操作步骤

页面顶部的三步指示（上传 → 确认 → 报告）随时显示你在流程中的位置。

  1. 打开网站，用自己的账号登录。
  2. 如果首页提示“还没有保存库存查询表”，在第二个文件框里选择库存查询表 （只需上传这一次，之后工具会一直保存）。
  3. 在第一个文件框里选择 Sell-Thru Map。
  4. 点击开始处理，等待进度条走完 — 文件较大时需要一两分钟， 期间请不要关闭页面。
  5. 进入确认页，核对提取结果并取消勾选不需要的款号 （详见下方“确认页说明”），然后点击生成按钮。
  6. 生成后进入运行报告页，点下载按钮获取 ProductsList 工作簿。报告页有独立网址，可以刷新、收藏，之后随时回看。

确认页说明

在你点击生成按钮之前，不会写入任何文件 — 最终结果由这一页决定。 清单中每一行是一个基础款号，同时显示它来自哪些标黄颜色款、 出现在哪些工作表、在库存查询表中匹配到多少行。

  • 默认全部勾选。勾选 = 写入 ProductsList； 取消勾选 = 不写入（被排除的款号会记录在运行报告里，方便追溯）。
  • 清单上方有三个快捷按钮：全选、全不选、 仅选有库存（一键取消所有没有匹配到库存的款号）。
  • 生成按钮上实时显示将写入的行数，随勾选变化自动更新。
  • 三种标记的含义：AI = 该款号来自 Claude 识别的 SKU 列，请先核对上方表格中的示例值是否确实是 SKU； 已记住 = 该列在之前的运行中已经人工确认过， 本次没有调用 AI；无库存 = 库存查询表中没有 匹配记录，即使勾选也只会出现在 Unmatched 工作表里。
  • 之前确认错了怎么办？把那个工作表的款号全部取消勾选 后生成，工具就会忘记这张表“已记住”的列，下次重新交给 AI 识别。

如何阅读运行报告？

报告分四个步骤，展示工具每一步做了什么，都可以点开逐项核对：

  1. 第 1 步：每个工作表找到了多少标黄单元格。点开能看到 每个标黄单元格的具体位置（比如 E19）、原始 SKU 和提取出的 基础款号——想在 Excel 里核对，按位置直接跳过去就行。
  2. 第 2 步：不同颜色款如何归并成基础款号。
  3. 第 3 步：每个基础款号在库存查询表里匹配到了哪些行 （条形码、颜色、尺码、成本价、零售价）。这些就是最终写进输出文件的数据。
  4. 第 4 步：输出文件是怎么生成的（排序规则、公式、留空的列）。

报告顶部会注明是谁上传的、谁确认生成的；如果确认时排除过款号， 也会在“确认时排除的款号”下逐一列出。

报告底部还有两个清单，需要留意：

  • 未匹配的基础款号：标黄了，但库存查询表里查不到。 请确认查询表是不是最新版本、有没有覆盖对应季节。这些款号也会写进输出 文件的 Unmatched 工作表。
  • 其他底色的 SKU 单元格：底色是灰色等其他颜色的单元格。 工具不会提取它们，列出来是方便人工确认有没有漏标。

PickUp 列：显式指定要补货的行

除了标黄，还可以用一个 PickUp 列明确指定要提取的行 — 完全绕开颜色识别的各种坑（浅黄看不清、被筛选隐藏等）。用法：

  1. 在工作表里新建一列，表头写 PickUp （大小写、空格、连字符不影响：pickup / Pick Up / PICK-UP 都可以； 表头需出现在前 15 行内）。
  2. 在需要补货的行，该列填 Y （也接受 yes、x、1、pickup、是，大小写均可）。
  3. 保存后照常上传。

规则：只要工作表有 PickUp 列，这张表就只按 该列提取：该列填了其他内容的行不会被选中（报告会列出无法识别的值）， 这张表上的标黄仅作参考 — 报告会单独列出“标黄但未标记”的款号供你核对。 没有 PickUp 列的工作表仍按标黄提取，所以每季的 Sell-Thru Map 不需要做任何改动。

什么样的才算“标黄”？（重要）

两种黄色都算：Sell-Thru Map 原本使用的浅黄 （颜色很淡， 肉眼容易漏看）和 Excel 标准的亮黄 。 尺码行的浅蓝条纹 只是表格样式，永远不算标黄。

常见疑问：“Excel 里明明只看到 1 个黄色，工具怎么报了 43 个？” 通常是两个原因：① 浅黄太淡，在屏幕上几乎看不出来；② 工作表开着筛选，大部分行被隐藏了——而工具读取的是 全部行，包括被筛选隐藏的行。 在 Excel 里点“数据 → 筛选”清除筛选，再对照第 1 步列出的单元格位置逐个核对。

关于输出文件

  • 每个匹配到的颜色/尺码占一行，按基础款号、颜色、尺码排序。
  • TotalCost 和 TotalSales 是公式 （数量 × 单价），修改数量后会自动重新计算。
  • 条形码保存为文本格式，不会丢失前导零， 也不会变成科学计数法。
  • Gift Recipient / Organization / Position 三列按模板要求留空。
  • 只保留最近 10 次的输出和报告，需要的文件请及时下载。

常见问题

  • 库存查询表被拒绝：列名和标准 13 列不完全一致。 请使用未经改动的原始导出文件；上传被拒绝时，之前保存的版本不受影响。
  • 提示文件过大：单次上传合计不能超过 200 MB。
  • 忘记密码：在登录页点击“忘记密码？”（邮箱确认后可用）； 或请任一管理员在“团队”页为你设置新密码。
  • 切换语言：左上角按钮随时切换中英文，选择会被记住。

What this tool does

Each season's Sell-Thru Map from Dior marks reorder styles in yellow — the note in cell E1 of the map says exactly that (标黄款式后续有REORDER补货, "yellow-marked styles get reordered"). This tool automates what used to be manual work:

  1. It scans every sheet of the map and finds each yellow-highlighted SKU;
  2. strips the trailing color code (X + 4 characters) to get the base style number (e.g. 644S16B7E72X5805 → 644S16B7E72);
  3. looks up every color and size variant of those styles in the stored stock query export;
  4. produces a filled, ready-to-use ProductsList workbook for download.

What you need before you start

  1. Your login — an admin creates your account on the Team page: you either receive an invite email and pick your own password, or the admin hands you an initial password. Every run records who uploaded the map and who reviewed & built the output.
  2. The Sell-Thru Map (.xlsx) with reorder styles marked yellow. Required for every run.
  3. The stock query export (.xlsx) — the standard 13-column export (Barcode, Sku, Division, Department, Season, Product reference, Color code, Size, Quantity, Unit Weighted Average Cost, Unit Retail Price incl. tax, Item Type, Path). You only upload it the first time, or when stock data changes — the tool keeps it for later runs.

Your first run, step by step

The three-step indicator at the top of every page (Upload → Review → Report) always shows where you are in the flow.

  1. Open the site and log in with your own account.
  2. If the front page says "No stock query export stored yet", pick the query export in the second file field (you only do this once — the tool keeps it for all later runs).
  3. Pick the Sell-Thru Map in the first file field.
  4. Click Process and let the progress bar finish — a large map takes a minute or two; keep the page open.
  5. On the review page, check what was extracted and untick anything that should stay out (see "The review page, explained" below), then press the build button.
  6. You land on the run report; click the download button to get the ProductsList workbook. The report page is a real URL — refresh it, bookmark it, or come back to it later.

The review page, explained

Nothing is written until you press the build button — this page decides the final result. Each row in the list is one base style number, shown with the highlighted colorways it came from, the sheets it appears on, and how many stock rows it matched.

  • Everything starts ticked. Ticked = written into the ProductsList; unticked = left out (the run report keeps a list of what you excluded, for the record).
  • The three buttons above the list are shortcuts: Select all, Select none, and Only with stock (unticks every SKU that matched no stock rows in one click).
  • The build button always shows exactly how many rows the workbook will contain — it updates as you tick and untick.
  • The three badges: AI = the SKU comes from a column located by Claude — first check the sample values in the table above to confirm they really are SKUs; remembered = that column was approved by a person on an earlier run, so no AI was needed this time; no stock = the SKU matched nothing in the stock query, so even ticked it only appears on the Unmatched sheet.
  • Approved something by mistake earlier? Untick every SKU of that sheet and build — the tool forgets that sheet's remembered columns and will ask the AI afresh next time.

How to read the run report

The report shows the work as four steps, each expandable for checking:

  1. Step 1: how many highlighted cells each sheet contained. Expand it to see every highlighted cell's position (like E19), its SKU, and the base extracted — jump to that cell in Excel if you want to verify by hand.
  2. Step 2: how colorways collapse into base styles.
  3. Step 3: for each base, the exact rows pulled from the stock query (barcode, color, size, cost, retail). These rows are what the output is built from.
  4. Step 4: how the workbook is written (sorting, formulas, blank columns).

The top of the report names who uploaded the map and who reviewed & built the run; if any SKUs were unticked at review, they are listed under "Excluded at review".

Two lists at the bottom deserve attention:

  • Unmatched bases — highlighted, but not found in the stock query. Check that your stored query export is recent enough and covers the season. They are also written to the output's Unmatched sheet.
  • Other fills detected — SKU cells with gray or other non-yellow fills. The tool does not extract them, but lists them so a human can confirm nothing was mis-marked.

The PickUp column: marking rows explicitly

Besides highlighting, you can select rows explicitly with a PickUp column — sidestepping every color-detection pitfall (invisible pale yellows, filter-hidden rows). How to use it:

  1. Add a column to the sheet with the header PickUp (case, spaces and dashes don't matter: pickup / Pick Up / PICK-UP all work; the header must sit in the first 15 rows).
  2. On every row you want to order, type Y in that column (also accepted: yes, x, 1, pickup, 是 — any casing).
  3. Save and upload as usual.

The rule: when a sheet has a PickUp column, that sheet is selected only by it: rows with anything else in the column are not selected (unrecognized values are listed on the report), and highlights on that sheet are reference-only — the report separately lists "highlighted but not marked" SKUs for you to check. Sheets without a PickUp column keep the yellow-highlight behavior, so the seasonal Sell-Thru Map needs no changes at all.

What counts as "highlighted"? (important)

Both yellows count: the map's native pale yellow (a theme color that looks very faint on screen and is easy to miss by eye) and Excel's standard bright yellow . The pale-blue banding on size rows is sheet styling and never counts.

Common confusion: "Excel shows me 1 yellow cell but the tool reports 43?" Two usual causes: ① the pale yellow is nearly invisible on screen; ② the sheet has an active filter hiding most rows — the tool reads all rows, including filter-hidden ones. Clear the filter in Excel (Data → Filter), then verify against the cell positions listed under Step 1.

About the output file

  • One row per matched color/size, sorted by base, color, size.
  • TotalCost and TotalSales are live formulas (quantity × unit price) — they recalculate if you edit quantities.
  • Barcodes are stored as text — no lost leading zeros, no scientific notation.
  • Gift Recipient / Organization / Position stay blank, as the template expects.
  • Only the last 10 outputs and reports are kept — download what you need.

Troubleshooting

  • Query file rejected — its header row doesn't exactly match the 13 standard columns. Use an unmodified export; a rejected upload never touches the previously stored copy.
  • Upload too large — the combined limit is 200 MB.
  • Forgot your password — use “Forgot your password?” on the login page (available once your email is confirmed), or any admin can set a new one for you on the Team page.
  • Language — the top-left button switches between English and Chinese at any time; the choice is remembered.
